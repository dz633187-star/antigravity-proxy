# AGDNS — локальный DNS для Antigravity

Локальный DNS-сервер, который перестаёт зависеть от провайдерского DNS: запросы
уходят по **DNS-over-HTTPS** (Google / Cloudflare / AdGuard), подменённые ответы
(`127.x.x.x`, `0.0.0.0`) отбрасываются, результат кэшируется, а при отказе одного
сервера запрос уходит на другой.

Ставится один раз и работает в фоне. Искать «рабочий DNS» каждый день больше
не нужно.

---

## Что было сломано

Провайдер подменяет DNS-ответы для доменов Google:

```
nslookup cloudcode-pa.googleapis.com
    -> 127.65.71.1        (заглушка, Antigravity не может подключиться)

через AGDNS:
    -> 172.217.118.4      (настоящий адрес Google)
```

Сам Google при этом доступен: TCP/TLS до `cloudcode-pa.googleapis.com` проходит,
API отвечает `401` (просит токен), а не блокирует по IP. То есть чинить нужно
именно DNS.

Вторая половина проблемы — **AGUnlocker**. Он ставит свои правила NRPT на
`cloudcode-pa.googleapis.com` и `daily-cloudcode-pa.googleapis.com`, и Windows
для этих двух доменов ходит не в системный DNS, а в резолвер анлокера
(`127.0.0.53`). Этот резолвер отдавал те же заглушки `127.65.71.x`, поэтому
Antigravity не работал даже при «правильном» системном DNS.

---

## Что делает установщик

1. Копирует файлы в `C:\ProgramData\AGDNS`.
2. Регистрирует задачу `AGDNS` — автозапуск при входе в систему, с
   автоперезапуском.
3. Регистрирует сторожа `AGDNS-Watchdog` — раз в 5 минут проверяет, что DNS
   отвечает; если нет — поднимает задачу. Он же возвращает правила NRPT на
   `127.0.0.1`, если AGUnlocker перепишет их на свой «мёртвый» DNS.
4. Переключает DNS активных интерфейсов на `127.0.0.1` (и `::1` для IPv6).
5. Переводит NRPT-правила Antigravity на `127.0.0.1`.
6. Сбрасывает кэш DNS и проверяет разрешение имён.

Прежние DNS-серверы сохраняются в `dns-backup.json` — для отката.

---

## Установка

1. Распакуйте папку `AGDNS` в любое место (например, на Рабочий стол).
2. Запустите **`install.cmd`** (двойной клик) → **«Да»** в окне UAC.
3. Дождитесь строки `ГОТОВО`.

После установки:

- закройте Antigravity полностью (включая иконку в трее) и запустите снова;
- если используете AGUnlocker — откройте его, проверьте, что в
  **«Настройки для опытных» → «Свой DNS»** стоит `127.0.0.1`, нажмите
  **«Включить всё»**.

> Установщик уже вписал `127.0.0.1` в настройки AGUnlocker
> (`%LOCALAPPDATA%\AGUnlocker\settings.json`, поле `custom_dns`). Если анлокер
> при запуске сбросит поле — впишите `127.0.0.1` вручную один раз.

Если у вас патчер без своего DNS (например, Open AG Patcher) — дополнительно
ничего настраивать не нужно: Antigravity берёт DNS из системы.

## Проверка

Двойной клик по **`check.cmd`**:

```
  Локальный DNS: отвечает на 127.0.0.1:53
  DNS интерфейсов: 127.0.0.1
  NRPT: правил нет (работает обычный DNS)

  OK   cloudcode-pa.googleapis.com    172.217.116.4, ...
  OK   daily-cloudcode-pa.googleapis.com ...
  OK   antigravity.google             34.111.134.1
  OK   ya.ru                          77.88.55.242, ...
```

Ручная проверка:

```powershell
Resolve-DnsName cloudcode-pa.googleapis.com -Type A -DnsOnly
```

Должен вернуть `172.217.x.x`, а не `127.65.71.1`.

## Удаление и откат

Двойной клик по **`uninstall.cmd`** → «Да» в UAC.

Скрипт остановит задачи, вернёт DNS из `dns-backup.json` (или поставит
«автоматически»), уберёт правила NRPT, ведущие на `127.0.0.1`, сбросит кэш и
удалит файлы. AGUnlocker при следующем «Включить всё» поставит свои правила
заново.

Сохранить файлы и журнал: `powershell -File uninstall.ps1 -KeepFiles`.

## Если что-то пошло не так

**Пропал интернет после установки.** Запустите `uninstall.cmd` — DNS вернётся к
прежним. Причина почти всегда одна: порт 53 занят другой программой (AdGuard,
dnscrypt, Pi-hole). Смотрите `C:\ProgramData\AGDNS\agdns.log` и
`C:\ProgramData\AGDNS\install.log`.

**Antigravity всё равно не работает.**

1. `check.cmd` — домены должны разрешаться в `172.217.x.x`.
2. AGUnlocker запущен, «Свой DNS» = `127.0.0.1`, нажато «Включить всё».
3. Antigravity перезапущен полностью.
4. В самом Antigravity: `Ctrl+Shift+P` → `Developer: Reload Window`.

Если после «Включить всё» домены снова отдают `127.65.71.x` — подождите 5 минут
(сторож вернёт правило) или запустите `install.cmd` ещё раз.

**Обновили или переустановили Python.** Запустите `install.cmd` заново: задача
автозапуска ссылается на конкретный путь `pythonw.exe`.

**Хочу закрепить конкретные IP.** В `C:\ProgramData\AGDNS\config.json`:
```json
"overrides": {
  "cloudcode-pa.googleapis.com": ["172.217.118.4", "172.217.113.4"]
}
```

Затем от администратора: `Restart-ScheduledTask -TaskName AGDNS`.

**Хочу другой набор DoH-серверов.** Там же список `doh`: `url` + `ips`
(IP обязательны — чтобы подключиться, даже когда системный DNS врёт).

## Как это устроено

```
Antigravity / Windows
        |
        v
127.0.0.1:53  (AGDNS, UDP + TCP)
        |
        |-- DNS-over-HTTPS -> dns.google          (8.8.8.8, 8.8.4.4)
        |-- DNS-over-HTTPS -> cloudflare-dns.com  (1.1.1.1, 1.0.0.1)
        |-- DNS-over-HTTPS -> dns.adguard-dns.com (94.140.14.14, ...)
        |
        |-- если все DoH недоступны: обычный DNS 8.8.8.8 / 1.1.1.1
        |-- если и там подмена: DNS роутера (только для внутренних имён)
        v
   проверка ответа: 127.0.0.0/8 и 0.0.0.0 отбрасываются
        |
        v
   кэш (TTL 30–3600 с) -> ответ клиенту
```

Запросы к DoH идут **по IP-адресам серверов**, а не по именам, поэтому подмена
системного DNS на них не влияет. TLS-сертификат проверяется по имени
(`dns.google`, `cloudflare-dns.com`) — подменить трафик незаметно нельзя.

Файлы:

| Файл | Назначение |
|---|---|
| `agdns.py` | сервер (только стандартная библиотека Python 3.8+) |
| `config.json` | DoH-серверы, кэш, overrides |
| `watchdog.ps1` | сторож: NRPT + перезапуск при падении |
| `install.cmd` / `install.ps1` | установка |
| `uninstall.cmd` / `uninstall.ps1` | откат |
| `check.cmd` / `check.ps1` | диагностика |
| `agdns.log`, `install.log` | журналы (в папке установки) |
| `dns-backup.json` | прежние DNS для отката |

---

## Ручной запуск (без установки)

```powershell
python agdns.py --verbose
```

Слушает `127.0.0.1:53`, но системный DNS всё равно нужно переключить вручную —
обычно проще запустить `install.cmd`.

Проверка уже запущенного сервера:

```powershell
python agdns.py --selftest 53
```
