# Заметки: что проверялось и почему не работало

Хронология диагностики Antigravity в РФ (ноябрь 2026). Полезно, чтобы не
повторять те же шаги.

## 1. Подмена DNS провайдером

`cloudcode-pa.googleapis.com` резолвился в `127.65.71.1` — заглушка РКН.
Настоящий адрес Google (`172.217.x.x`) при этом доступен: TLS проходит, API
отвечает `401` (просит токен). То есть блокировка была именно на DNS.

Решение: локальный DoH-резолвер (`agdns/`).

## 2. Antigravity Unlocker

Анлокер ставит NRPT-правила на два домена Google и направляет их в свой
резолвер `127.0.0.53`. На практике тот отдавал ту же заглушку `127.65.71.x`.

Его релеи `ag-proxy*.nova-app.eu` физически находятся в Санкт-Петербурге
(`185.185.68.117`, `185.251.89.120`, `212.116.115.237`, AS35278 SPRINTHOST) —
то есть выхода из РФ не дают. Отсюда и «каждый день новый DNS».

Вывод: анлокер полезен как патчер (`ineligible → inexigible`, `isGoogleInternal`),
но не как прокси.

## 3. Проверка гипотез про IP

- Все 8 адресов `172.217.x.x` отвечают за 0,3 с — DNS и сеть в порядке.
- Порт 443 сервера из 25 стран открыт, из России и с мобильного — нет
  (блокировка IP на уровне операторов).
- Запрос Antigravity к Google шёл через Амстердам (лог Xray:
  `accepted //daily-cloudcode-pa.googleapis.com [http >> nl]`), прямой доступ
  был заблокирован файрволом — и всё равно `400 User location is not supported`.
- Отсюда вывод: Google смотрит не только на IP. Датацентровые адреса
  (VPS, Cloudflare) не подходят — нужен резидентный выход.

## 4. Что в итоге заработало

```
Antigravity → 127.0.0.1:10809 (Xray) → резидентный HTTP-прокси (США) → Google
```

Локальный Xray настроен как HTTP-клиент к внешнему прокси, приложение получает
`AG_LS_PROXY=http://127.0.0.1:10809`. VPS и Cloudflare в этой цепочке не
участвуют — оставлены как резерв.

## 5. Грабли

- **BOM в JSON.** PowerShell 5.1 пишет `Set-Content -Encoding UTF8` с BOM, Xray
  такой конфиг не читает (`invalid character '\ufeff'`). Писать через
  `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`.
- **BOM в .ps1.** Без BOM PowerShell 5.1 читает кириллицу как ANSI и ломает
  парсинг. Все `.ps1` сохранять в UTF-8 **с** BOM.
- **QUIC.** В ответах Google есть `Alt-Svc: h3`. HTTP-прокси не переносит UDP,
  поэтому стоит блокировать UDP/443 для приложения, чтобы оно не уходило мимо.
- **Анлокер перезаписывает `AG_LS_PROXY`** на `127.0.0.1:53129` при запуске.
  Если используете своё приложение — анлокер не запускайте.
- **trycloudflare-туннели** дают новый адрес при каждом старте и умирают вместе
  с процессом. Для постоянства нужен именованный туннель на своём домене.
